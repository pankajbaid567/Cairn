## Checked against the design, and the two places that differ from its text
- FV9: reasoning tokens count as output. `WorkersAiLlm` uses `max_tokens` as the output term of the neuron estimate, and a result with empty or whitespace text and `finish_reason` `length` raises `WorkersAiError("bad_response")`. `parse_text` already rejects `content: null` (the reasoning used the whole bound) with the same code. A non-empty text cut off at the bound is returned with `finish_reason="length"` so the caller can decide. `LlmResponse` has a `finish_reason` field the design sketch does not list.
- Request body: design §13 sketches `"max_tokens"`; the adapter sends `"max_completion_tokens"` because FV8 and FV9 record `max_tokens` as deprecated for gemma and glm. The text call also uses a 60 s read timeout (`LLM_READ_TIMEOUT_S`), because reasoning makes generation slower than the 30 s default and a retry after a cut-off would pay twice.
- The adapters raise `ValueError` for an empty text, query or passage before any call (the models reject empty input); the fakes accept them.
- `FakeReranker` counts each distinct query token once. The design text says "number of shared non-stopword tokens"; the distinct count keeps repeated query words from inflating a score and is still independent of position.

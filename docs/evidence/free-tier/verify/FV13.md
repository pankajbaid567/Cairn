## What the check found that the design text did not say

- **The ft-app healthcheck needs far longer limits at 0.1 CPU.** With the design's `interval: 10s`, `timeout: 8s`, `retries: 12` every check failed with "Health check exceeded timeout (8s)". A `docker exec cairn-ft-app-1 python -m cairn_api.healthcheck` takes about 16 s of wall time there (two runs: 16.4 s and 16.6 s; exit status 0): the exec'd process shares the 10 ms per 100 ms quota with the app. `/healthz` through the published port took 13.9 s once, while two checks were running. The compose file now uses `interval: 30s`, `timeout: 60s`, `retries: 6`, `start_period: 180s`. With those, `up --wait` finished: `ft-app` healthy 133 s after the start. (In the first run, with the old values, DBOS had launched about 86 s after the start, and `/readyz` answered 200 with the header and 404 without it; `/healthz` 200.) Task 6.2's tests must expect slow responses at 0.1 CPU (use generous timeouts, for example 60 s), and the RAM check (task 6.3) should take samples at a few seconds' spacing, not rely on probe speed.
- **Memory at idle** (about 4 minutes after start): `ft-app` 79 MiB of 512, `ft-db` 129 MiB of 512. These are single `docker stats` samples, not the RAM report of task 6.3.
- **Roles and extensions in `ft-db`** after `ft-admin-init` and `ft-db-init`: `cairn_admin` NOSUPERUSER CREATEROLE CREATEDB BYPASSRLS; `cairn_owner`, `cairn_app`, `cairn_dbos` all false on the same four attributes; database `cairn` carries `btree_gist 1.8`, `vector 0.8.6`, `plpgsql`; `pg_available_extensions` has no `pg_search`.
- **Bring-up order** with `docker compose --profile freetier up --wait --build`: `ft-db` healthy after about 11 s, both init containers exit 0, then `ft-app`. Both init services carry their own `build` block for the tag `cairn-python:local` (same as `db-init`), so the profile builds from a clean checkout.
- **Compose races.** Running `docker compose … down` and `make up` at the same moment makes the network removal fail with `Resource is still in use` or the start with `network not found`. That was my own overlapping commands, not a profile defect; run the two profiles one after the other.

# FV10: Workers AI data terms and the licenses of the four default models

Resolved 3 Nov 2026 (task 10.1). Requirements 18.3 and 16.6; design FT-24, §15 and the threat model (TM-13). Content was rephrased for compliance with licensing restrictions; the URLs are the authority. No Cloudflare, Neon or Render call was made with user credentials: only public pages were read.

## Workers AI data handling

Source: [Cloudflare docs: Workers AI, Data usage](https://developers.cloudflare.com/workers-ai/privacy/) (read 3 Nov 2026).

| Question | Answer |
|---|---|
| Is request content used to train models? | No. Cloudflare says it does not use Customer Content processed by Workers AI to train AI models. |
| Is content retained? | Standard inference requests that use no stateful feature are not retained once the response is delivered ("zero data retention"). Storage you direct is the exception: R2, KV, Durable Objects, Vectorize, AI Gateway logging or caching, application logs, and asynchronous or batch features. Cairn uses none of these. |
| What counts as Customer Content? | Inputs, outputs, embeddings and any training or adaptation data. So chunk texts sent for embedding, reranked passages and packed evidence are all covered. |
| What does Cloudflare keep? | Operational metadata for operating, securing, supporting and billing the service (account and model identifiers, timestamps, request and response sizes, token or neuron counts, latency, request source, status codes). The page says this metadata holds no Customer Content. |
| Who else sees the content? | Not other Cloudflare customers. If AI Gateway forwards to another provider, that provider's terms apply (Cairn does not use AI Gateway). |
| Model licenses | Cloudflare does not create or train the models; each is under its publisher's license, which the customer must review. |

Each of the four model pages on developers.cloudflare.com (bge-small-en-v1.5, bge-reranker-base, gemma-4-26b-a4b-it, glm-4.7-flash) shows "Zero data retention: Yes" in its Model Info block.

What the user still has to confirm: the exact Cloudflare agreement for the account (Self-Serve Subscription Agreement unless the account is Enterprise). That is FU-level knowledge; nothing in the repo depends on it. The corpus stays synthetic (decision D20), so the egress in TM-13 carries no real company data.

## Licenses of the default models

Read from the publishers' Hugging Face model cards on 3 Nov 2026.

| Workers AI model | License | Where it is stated |
|---|---|---|
| `@cf/baai/bge-small-en-v1.5` | MIT (the card says FlagEmbedding and the released models are MIT, commercial use free) | [BAAI/bge-small-en-v1.5](https://huggingface.co/BAAI/bge-small-en-v1.5), section "License" |
| `@cf/baai/bge-reranker-base` | MIT (same statement) | [BAAI/bge-reranker-base](https://huggingface.co/BAAI/bge-reranker-base), section "License" |
| `@cf/google/gemma-4-26b-a4b-it` | Apache-2.0 | [google/gemma-4-26B-A4B-it](https://huggingface.co/google/gemma-4-26B-A4B-it), header line "License: Apache 2.0" |
| `@cf/zai-org/glm-4.7-flash` | MIT | [zai-org/GLM-4.7-Flash](https://huggingface.co/zai-org/GLM-4.7-Flash), front matter `license: mit` in its README |

**Differs from the design.** Design §15 and the license table of the threat-model section list Gemma under "Gemma terms (FV10, OQ-5)", assuming the older Gemma terms of use. The Gemma 4 card states Apache-2.0, which is on the license allowlist, so OQ-5 needs no restriction handling. The Cloudflare model page for Gemma 4 has a "Terms and License" link whose target the fetch tool did not expose; the Hugging Face card is the source used. If Cloudflare's link points at different terms, the user should reconcile it (not blocking: the models are called as a hosted service, never redistributed).

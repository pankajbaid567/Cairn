Long-running core limits today: 1024m (db). With the design's later services (api 384m, worker 384m, web 64m) the sum is 1856m, inside the 4 GB budget (Requirement 4.5). Idle db use right after init: about 133 MiB.

Hardening on db-init (the `x-python-app` anchor, for api and worker to reuse): `user 10001:10001`, `read_only: true`, `tmpfs /tmp`, `cap_drop: [ALL]`, `no-new-privileges`. db-init runs fine under all of them. The `db` service keeps the image defaults because the entrypoint needs root to prepare the data directory.

## Port 5432 was taken

`taskflow-postgres` (another project's container, up for 5 days) publishes `0.0.0.0:5432`, so `up-db` failed with "port is already allocated". I did not touch that container. I changed the two host-port values in the local `.env` (`CAIRN_DB_PORT`, `CAIRN_TEST_ADMIN_PORT`) to 55432 with `sed`, no secret read or printed. Compose publishes `127.0.0.1:55432 -> 5432` (checked with `docker port`). `.env.example` keeps 5432, since that is right for a clean machine. Anyone else running tools on the host (tests in 4.2, `cairn-db status`) reads `.env`, so they pick up 55432 automatically. Inside the compose network the port is always 5432 (`db-init` sets `CAIRN_DB_PORT: "5432"` itself).

## Behavior worth knowing

- **Extensions come from template1.** `cairn` and `cairn_dbos` both contain postgis, postgis_topology, postgis_tiger_geocoder, pg_ivm, fuzzystrmatch and pg_stat_statements besides the required three. Harmless for `/readyz`; mention in ADR-0001 or revisit with `TEMPLATE template0` in a later bootstrap change (V1.md).
- **Auto-tuning.** `shared_buffers` is 256MB (design assumed 128MB), `work_mem` 15MB, `maintenance_work_mem` 64MB. It runs on first boot only, so a changed `CAIRN_DB_MEM_LIMIT` needs `make db-reset`.
- **`up` re-runs db-init.** `docker compose --profile core up --wait` starts the stopped one-shot again; this is intended (idempotent) and shown as `Healthy` while it runs.
- The db-init log lines are JSON from `cairn_core.bootstrap` plus the plain lines from `cairn-db`; neither prints a password or verifier (the statement text is never logged).
- `log_statement` is at the image default `none` (checked with `SHOW`).
- A `down` (not `down --volumes`) keeps `cairn_pgdata`, so roles and data survive a restart.

## Deviations from the design

| Design | Done here | Why |
|---|---|---|
| Image reference `paradedb/paradedb:${PARADEDB_TAG}@${PARADEDB_DIGEST}` | Literal tag and digest in `image:` | `scripts/licenses.py` reads literal references; Requirement 4.8 is easier to check |
| Tag example `0.26.2-pg18` | `0.26.3-pg18` | Newest `*-pg18` on 27 Oct 2026 (V1) |
| db-init image `cairn-python:local` | Same name, built with `PACKAGE=cairn-core` | One Dockerfile for all Python services; api and worker will build with their own `PACKAGE` |
| "Keep server defaults (128 MB shared_buffers)" | 256MB, from the image's auto-tuning | The image tunes from the memory limit; V1.md |
| Host port 5432 | 55432 in the local `.env` only | Port taken by another project's container |
| `up-db` as `up --wait db` | `up --wait --no-deps db` | `db` has no dependencies; explicit |
| `compose-check` "per profile" | obs and experiments are checked together with core | Compose cannot render a selection without a service |
| Volumes: all three declared | `pgdata`, `prometheus-data`, `grafana-data` declared; the last two are unused until task 10.1 | Design §4 lists them |
| db-init hardening not in the design | read-only root, dropped capabilities, no-new-privileges | Cheap and works; applies to api and worker through the anchor |

## Notes for later tasks

- 4.2 (fixtures and integration tests): host settings come from `.env`: `CAIRN_TEST_ADMIN_HOST=127.0.0.1`, `CAIRN_TEST_ADMIN_PORT=55432` here, user `postgres`, password `POSTGRES_PASSWORD`. Never hard-code 5432; read `CAIRN_TEST_ADMIN_PORT`. The database already has roles, `cairn`, `cairn_dbos` and migration 1, so the fixtures' `bootstrap()` call must be a clean no-op (it is idempotent: roles are `ALTER`ed). The container name is `cairn-db-1`; `docker exec cairn-db-1 psql -U postgres` works without a password (local socket trust). `pg_hba` accepts password auth over TCP, so the app and owner roles can be tested through the published port. Template1 already contains the extra extensions, so a test database made by `bootstrap_database` has them too.
- 5.4 (api service): reuse the `x-python-app` anchor and the Dockerfile with `build.args.PACKAGE: cairn-api`; set `CAIRN_DB_HOST: db`, `CAIRN_DB_PORT: "5432"`, `CAIRN_APP_DB_PASSWORD`, and nothing else secret. `depends_on: db-init: condition: service_completed_successfully` works under `up --wait` (V3). The runtime image has no `wget`/`curl`, so the healthcheck must be `python -m cairn_api.healthcheck`. Publish `127.0.0.1:8000:8000`. The root filesystem is read-only with `/tmp` as tmpfs.
- 6.3 (worker service): same pattern with `PACKAGE: cairn-worker`; the heartbeat file lives in `/tmp/cairn-worker`, which the tmpfs covers. The worker connects as `cairn_dbos` to database `cairn_dbos` on host `db`. Stop grace period needs to be above the 10 s shutdown budget.
- 7.2 (web service): not based on this Dockerfile. The `depends_on: api: service_healthy` goes in compose.
- 8.1 (stack targets): `mk/db.mk` already defines `COMPOSE` (with `?=`), `DB_VOLUME`, `up-db`, `db-init`, `db-status`, `db-reset` and `compose-check`. `make up` can be `$(COMPOSE) --profile core up --wait` (V3); on failure print `ps` and `logs --tail 50`. `make down` should not use `--volumes`. `make db-reset` already removes `cairn_pgdata`, so do not define it again. `up-obs` is `OTEL_TRACES_EXPORTER=otlp $(COMPOSE) --profile core --profile obs up --wait`.
- 10.1 (obs): add services under `profiles: [obs]`; `prometheus-data` and `grafana-data` volumes already exist. `compose-check` already runs `--profile core --profile obs`. Add each image row to `IMAGE_LICENSES` only if missing (they already exist).

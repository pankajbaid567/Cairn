# V12: `opentelemetry-instrumentation-psycopg` with psycopg 3 async connections

Date: 27 Oct 2026. Resolved by task 5.1. **Result: yes, it traces async connections.**

| Item | Result |
|---|---|
| Versions | opentelemetry-instrumentation-psycopg 0.66b1 (with `-dbapi` 0.66b1), psycopg 3.3.6 (binary, libpq 18.0.6), SDK 1.45.1, server PostgreSQL 18.6 (ParadeDB image from compose) |
| Instrumentor | `PsycopgInstrumentor().instrument(tracer_provider=...)` wraps `psycopg.connect`, `psycopg.Connection.connect` **and** `psycopg.AsyncConnection.connect` (source: `_instrument` calls `dbapi.wrap_connect` three times, the third with `DatabaseApiAsyncIntegration`) |
| Warnings | None. `python -W error` imports, instruments, connects, queries and (for the offline case) fails to connect without a warning. The pytest suite runs with `filterwarnings = ["error"]` and the instrumentor stays out of it (tests stub it) |
| Live check | `cairn_core.health.probe_database` (an `AsyncConnection`, two statements) against the compose `db` as `cairn_app`, instrumented with an in-memory exporter: 2 spans, both `SpanKind.CLIENT`, one per statement (`SELECT current_setting('server_version_num')…`, `SELECT max(version) FROM cairn_meta.schema_migrations`). Attributes: `db.name`, `db.statement`, `db.system`, `db.user`, `net.peer.name`, `net.peer.port`. No password in any attribute |
| What is not a span | Connecting, `BEGIN` and `COMMIT` (`conn.transaction()` issues them through the connection, not a traced cursor) |
| Parameters | `capture_parameters` defaults to false and stays false, so bound values (here the extension-name list) never reach a span. The SQL text is recorded as `db.statement` |
| Failed connect | With the instrumentor active, a refused connection still raises `psycopg.OperationalError` as before and `probe_database` returns `db_unreachable`. No span is created for a failed connect |
| Scope | The patch is global to the process. `cairn_api.main.create_app` applies it once, after `configure_tracing`, passing the provider. `build_app` does not instrument psycopg, so unit tests and other callers of `build_app` stay unpatched |

## Decision

Keep `opentelemetry-instrumentation-psycopg==0.66b1` and the single async probe connection per `/readyz` call. Requirement 9.6 ("a client span for each database query") holds for both statements of the probe.

Commands:

```text
uv run python -W error <throwaway script>   # load ApiSettings from .env, instrument with an in-memory exporter, run probe_database, print the spans
```

The script was a throwaway outside the repo (about 20 lines, not kept); the equivalent unit coverage is `test_create_app_wires_logging_tracing_and_psycopg_instrumentation` (wiring) and the API span test (server span and trace id in the log).

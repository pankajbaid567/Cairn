## The pin is shared

`mk/security.mk` does not repeat the reference. `GITLEAKS_IMAGE` is read from the `entry:` line of the gitleaks hook in `.pre-commit-config.yaml` with `sed`, so the hook and `make secrets` always run the same image. The target stops with exit 2 and a message if no digest-pinned entry is found. A bump in the hook is the only edit needed.

## Behaviour on this repo

- `make secrets`: 3 seconds, about 760 KB scanned, `no leaks found`.
- The default rules flag the local `.env` (five `generic-api-key` findings for the generated passwords, values redacted). `.gitleaks.toml` therefore skips the path `.env` only. It is gitignored, listed in `.dockerignore`, and holds random local secrets by design. `.env.example` is not allowlisted and is not flagged: `change-me` has too little entropy for any default rule. A real secret pasted into `.env.example` fails the scan (checked).
- Generated or third-party directories that git ignores are skipped by path: `.git`, `.venv`, `node_modules`, `.pnpm-store`, `__pycache__`, the tool caches, `dist` and `var`.

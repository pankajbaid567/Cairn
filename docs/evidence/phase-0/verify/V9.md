# V9: commit SHAs for the GitHub Actions used

Date: 27 Oct 2026. Resolved by task 11.2.

## Method

`gh` is not installed and the unauthenticated GitHub REST API answered `403 rate limit exceeded` (60 requests per hour, already used), so the tags were resolved without the API:

1. Latest release tag: the redirect of `https://github.com/<owner>/<repo>/releases/latest` (`curl -o /dev/null -w '%{redirect_url}'`).
2. Tag to commit: `git ls-remote --tags https://github.com/<owner>/<repo> refs/tags/<tag> 'refs/tags/<tag>^{}'`. For an annotated tag the `^{}` line is the commit the tag points to, and that is the SHA to pin. A lightweight tag has no `^{}` line and its own line is the commit.
3. Cross-check: `https://github.com/<owner>/<repo>/commit/<sha>` answers 200 for every SHA, `action.yml` at that SHA was fetched from `raw.githubusercontent.com` to confirm the inputs used and the runtime (`node24` for all five).

A test compares the uv, Node and pnpm pins with the repo's own files, so a bump in one place fails until the other follows.

## Caveats

- A pinned SHA does not follow a moved tag; that is the point. Bumping an action means repeating steps 1 to 3 and editing the SHA and the comment together.
- Nothing was run on GitHub: there is no remote yet (user step U4). `make actionlint` and the workflow tests are the local checks, and runner-side behavior (setup-uv cache, pnpm/action-setup with an explicit version, gitleaks in a container on a runner checkout) is unverified until the first remote run.
- No action is given a secret, and the workflow declares only `permissions: contents: read`. `setup-uv` falls back to the default `github.token` (read-only) to download uv.

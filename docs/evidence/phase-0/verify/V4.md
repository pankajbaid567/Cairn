# V4: client-side SCRAM-SHA-256 verifiers through psycopg

Date: 27 Oct 2026. Resolved by task 3.2.

| Item | Result |
|---|---|
| psycopg | 3.3.6, binary implementation, libpq 18.0.6 (`psycopg.pq.version()` = 180006) |
| API | `psycopg.pq.PGconn.encrypt_password(passwd: bytes, user: bytes, algorithm: bytes \| None = None) -> bytes` (wraps `PQencryptPasswordConn`). Reachable as `conn.pgconn.encrypt_password` on a `psycopg.Connection` |
| Needs a live server? | **Not with an explicit algorithm.** On a `PGconn` whose connection failed (`status` = CONNECTION_BAD, socket path that does not exist), `encrypt_password(b"pw", b"u", b"scram-sha-256")` returned `SCRAM-SHA-256$4096:<salt>$<StoredKey>:<ServerKey>`. With `algorithm=None` libpq asks the server for `password_encryption` and fails offline: `OperationalError: password encryption failed: no connection to the server` |
| Other algorithms | `b"md5"` works; an unknown name raises `OperationalError: password encryption failed: unrecognized password encryption algorithm "bogus"`. The error text does not contain the password |
| Output | 4096 iterations, 16-byte random salt, so two calls with the same password differ |
| Pure-Python check | `hashlib.pbkdf2_hmac("sha256", pw, salt, iterations)` plus HMAC "Client Key" / "Server Key" reproduces libpq's verifier exactly when given libpq's salt and iteration count (unit test `test_python_verifier_matches_libpq_for_the_same_salt_and_iterations`) |

## Decision

`cairn_core.bootstrap.ScramEncryptor` calls `conn.pgconn.encrypt_password(password, role, b"scram-sha-256")` on the superuser connection bootstrap already holds. The algorithm is explicit, so the result does not depend on the server's `password_encryption` setting (PG18 defaults to scram-sha-256 anyway).

Fallback when that call is missing or raises (`AttributeError`, `NotImplementedError`, `psycopg.Error`): `scram_sha256_verifier`, a pure-Python implementation of the same format. It supports ASCII passwords only, because PostgreSQL applies SASLprep first; a non-ASCII password raises `BootstrapError` without echoing it.

This differs from the design's documented fallback (`ALTER ROLE … PASSWORD` with a plaintext `Literal`): the Python verifier keeps plaintext out of every statement even when libpq encryption is unavailable, so Requirement 5.8 holds on both paths. `role_statement` also refuses any value that is not shaped like a SCRAM-SHA-256 verifier.

Commands:

```text
uv run python -c "import psycopg.pq as pq; c = pq.PGconn.connect(b'host=/nonexistent-cairn dbname=x connect_timeout=1'); print(c.status, c.encrypt_password(b'pw', b'u', b'scram-sha-256')[:30]); c.encrypt_password(b'pw', b'u')"
```

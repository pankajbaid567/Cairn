## How the generator decides what is a secret

A value is a secret when it is exactly `change-me`, unquoted or in single or double quotes, with nothing after it except an optional comment. Variable names are not consulted. Comments, blank lines, key order and every other value are copied unchanged. `change-me-later` and `change-me` inside comments are left alone.

- `render(template, token_source)` is pure apart from the token source. A source that returns fewer than 24 characters, the placeholder, or characters outside `[A-Za-z0-9_-]` raises `EnvTemplateError`.
- The default source is `secrets.token_urlsafe(24)`, which gives 32 characters.
- `write_env` creates `.env` with `O_CREAT | O_EXCL | O_NOFOLLOW` and mode 0600, then `fchmod`s to exactly 0600 whatever the umask. An existing file, or a dangling symlink, raises `FileExistsError` and is never touched.
- Exit codes: 0 written, 1 `.env` exists, 2 template unreadable. The success message prints the count of secrets, never values.
- A unit test fails if a template variable whose name contains PASSWORD, SECRET, TOKEN or KEY is not a placeholder, and another pins the exact secret list.

## Deviations from the design

- Test admin settings are `CAIRN_TEST_ADMIN_HOST`, `_PORT` and `_USER` only. The password is `POSTGRES_PASSWORD`, so there is no second superuser password to keep in sync. Design §15 says the fixtures read `CAIRN_TEST_ADMIN_*` settings; task 4.2 must take the password from `POSTGRES_PASSWORD`.
- Quotes around a quoted placeholder are dropped in the generated value (tokens are URL-safe). The template uses none.
- Extra variables beyond the task list, all from design §4 and §7: `CAIRN_ENV`, `CAIRN_LOG_LEVEL`, `CAIRN_DB_PORT`, `CAIRN_DB_NAME`, `CAIRN_DB_TIMEOUT_S`, `CAIRN_APP_DB_USER`, `CAIRN_DBOS_DB_NAME`, `CAIRN_DB_MEM_LIMIT`, `OTEL_EXPORTER_OTLP_ENDPOINT`.
